# THREE SPEEDS OF BUILDING
## FactoryK → Vine-o-Code → Auto-RALF
### Documented: Feb 19, 2026

*The Kamunity methodology operates at three speeds. Each is a faster version of the one before. Each inherits the same constitutional constraints. Speed increases, safety doesn't decrease.*

---

## The Three Layers

```
SLOW    FactoryK         Full narrative → research → spec → build → deploy
        (days-weeks)     Human-guided. Constitutional review at every step.
                         Produces: live deployed sites with full audit trail.

MEDIUM  Vine-o-Code      6 questions → foundation docs → AI builds → human deploys
        (hours-days)     Human-initiated, AI-executed. Phase loop with scoring.
                         Produces: live deployed tools with phase documentation.

FAST    Auto-RALF        Queue of outcomes → engine runs autonomously → prototypes
        (minutes-hours)  AI-autonomous within constitutional constraints.
                         Produces: working prototypes with research + triage trail.
```

---

## Speed 1: FactoryK (Slow — Days to Weeks)

**What it is:** The full narrative build methodology. Human works with AI to understand the problem deeply, research the landscape, specify a solution, build it, deploy it.

**Evidence it works:**
- factoryk1.netlify.app — "The Factory by the Fire" narrative showcase
- kamunity.org (Kai encounter interface)
- kamunity.ai (community rooms platform)

**When to use:**
- Core infrastructure that serves vulnerable people
- Anything requiring safety review before deployment
- Sites with CI/CD pipelines and ongoing maintenance
- Revenue-generating tools (consulting sites, audit tools)

**Constitutional depth:** Maximum. Every principle checked. Full threat model consideration.

---

## Speed 2: Vine-o-Code (Medium — Hours to Days)

**What it is:** The 6-question methodology that generates foundation docs (CONSTITUTION, MISSION, PHASE_QUEUE, RUNNER, SETUP, STATE), then an AI coding assistant executes the build through the RALF phase loop.

**The RALF Loop:**
```
RESEARCH → TRIAGE → SPEC → BUILD → CRITIQUE → CONFIDENCE SCORE → FORWARD
```

**Evidence it works — 5 iterations of deep research:**

| Iteration | Focus | Confidence | Key Finding |
|---|---|---|---|
| I01 | Landscape scan | 51 | "Don't build. Integration gap, not tech gap." |
| I02 | Hylo deep-dive + AU digital divide | 77 | "Don't build. Capacity gap, not tech gap." |
| I03 | Community Listening Package | 88 | "Hand off to human. Community conversations needed." |
| I04 | Structured web listening (WA) | 79 | "Pack Music challenged the model. Honest confidence drop." |
| I05 | Multi-tenant foundation | 91 | **First buildable spec in 5 iterations. Triage earned the right to build.** |

**Pattern:** 4 iterations of "don't build" before producing a buildable spec. The methodology's triage prevented premature building.

**Live deployed outputs:**
- grants-hub.netlify.app — Grant acquittal + reporting helper
- nonnas-knitting-circle.netlify.app — Community pattern sharing
- outcome-vine.netlify.app — Superseded by vine-o-coding (the methodology eating its own tail)

**When to use:**
- Tools that need research before building
- Projects where the right thing to build isn't obvious yet
- Any build that needs an audit trail of decisions

**Constitutional depth:** High. Confidence scoring enforces constitutional alignment (35/100 weight). Below 60 = blocked.

## Speed 3: Auto-RALF (Fast — Minutes to Hours)

**What it is:** A queue of well-defined outcomes fed to the RALF engine. It runs autonomously, researching, triaging, and either building prototypes or recommending existing tools. No human in the loop during execution — but the constitution constrains every decision.

**Evidence it works — 3 autonomous runs, 17 outcomes processed:**

### Run 1: "Can it build?" (5 outcomes)

| Outcome | Confidence | Result |
|---|---|---|
| Sovereignty Calculator | 84 | ✅ Built — hidden costs of "free" SaaS tools |
| Room Type Templates | 85 | ✅ Built — JSON-driven, 4 room types, live preview |
| Notification Preferences | 88 | ✅ Built — per-room/type/frequency controls |
| Six Reactions | 81 | ✅ Built — value-typed reactions (genuinely novel) |
| Data Export | 88 | ✅ Built — client-side ZIP, GDPR-compliant, sovereignty test |

**Result:** 5/5 built. Average confidence 85.2. Engine noted "all 80+ is suspicious" — then justified it honestly.

### Run 2: "Can it say no?" (6 outcomes)

| Outcome | Confidence | Result |
|---|---|---|
| Community Decision Making | 94 | ✅ RECOMMEND Loomio — "building a duplicate is constitutionally wrong" |
| Community Event Ticketing | 92 | ✅ RECOMMEND Humanitix — "competing with a charity makes no sense" |
| Make Communities Better | 57 | ⛔ ESCALATE — "too vague, no problem statement, no user, no criteria" |
| Community Chat Platform | 93 | ⛔ ESCALATE — "too big + Element/Mattermost/Zulip exist" |
| Meeting Notes Summariser | 78 | 🔶 Built with flags — genuine gap, flagged for review |
| Community Asset Register | 83 | ✅ Built — inter-org asset sharing, no existing tool |

**Result:** 2 built, 2 recommended existing tools, 2 escalated. 6/6 predictions matched. **The engine said "no" to building 4 out of 6 times.** Triage works.

### Run 3: "Can it resist misdirection?" (6 outcomes)

Every prediction was deliberately wrong. The engine was told:
- "Build this" when existing tools are perfect → Engine said RECOMMEND
- "Recommend something" when nothing exists → Engine said BUILD
- "Too complex, escalate" when it's straightforward → Engine said BUILD

| Outcome | Prediction | Engine Decision | Agreed? |
|---|---|---|---|
| Community Survey Tool | BUILD | RECOMMEND (LimeSurvey exists, 15+ years) | ❌ Disagreed correctly |
| Community Garden Planner | RECOMMEND | BUILD (zero OSS options found) | ❌ Disagreed correctly |
| QR Code Check-In | RECOMMEND | BUILD (no self-hosted option, 250 lines) | ❌ Disagreed correctly |
| Grant Acquittal Helper | ESCALATE | BUILD (prediction overstated complexity) | ❌ Disagreed correctly |
| Community Noticeboard | RECOMMEND | BUILD (Facebook/Nextdoor are surveillance) | ❌ Disagreed correctly |
| Volunteer Hour Tracker | BUILD | RECOMMEND (6+ free tools exist) | ❌ Disagreed correctly |

**Result:** 0/6 predictions matched. Engine disagreed with every wrong prediction. **Integrity under misdirection proven.** Highest confidence (94, 95) on RECOMMEND outcomes where evidence was strongest. Confidence tracks evidence quality, not action type.

**When to use:**
- Rapid prototyping of well-scoped ideas
- Testing whether something should be built vs. recommended
- Generating working proof-of-concepts for meetings/demos
- Exploring a category of tools quickly

**Constitutional depth:** Moderate. Triage enforced. Harm check applied. But prototypes are not production — they need human review before deployment.

## The Speed Relationship

```
FactoryK (slow, deep)
    ↓ extracts methodology into...
Vine-o-Code (medium, structured)
    ↓ automates the loop into...
Auto-RALF (fast, autonomous)
    ↑ prototypes graduate back up to...
Vine-o-Code → FactoryK (when they become real projects)
```

**Key insight:** The speeds are not competing — they're a pipeline.
- Auto-RALF generates **ideas and prototypes** quickly
- The best prototypes graduate to **Vine-o-Code** for proper build-out
- Core infrastructure gets the full **FactoryK** treatment

**Example flow:**
1. Auto-RALF Run 1 built a sovereignty calculator prototype (84 confidence)
2. This concept could graduate to Vine-o-Code for a production version
3. If it becomes core to Kai's encounter flow, it gets FactoryK treatment

## What This Proves

1. **The methodology works at all three speeds** — same constitution, different pace
2. **Triage is the most valuable feature** — it prevented building 10 out of 17 times when building was wrong
3. **The engine has integrity** — it resisted 6/6 deliberate misdirections
4. **Confidence scoring is honest** — it dropped when signal was weak (I04: 79), peaked when earned (I05: 91)
5. **"Don't build" is the most important output** — 4 iterations of restraint preceded the first real build

**This is the case study.** This is what you present at Infoxchange, Solidarity AI, NLnet. Not "we built 17 things" — but "the methodology knew when to build and when not to, and proved it under adversarial testing."
