# Critique: community-decision-making

## Constitutional Questions

### 1. Does this serve community sovereignty?
**Yes.** Recommending Loomio serves sovereignty better than building a new tool. Loomio is open source (AGPL-3.0), self-hostable, and built by a worker-owned cooperative. Communities retain full control of their decision data, especially if self-hosted.

### 2. Could this concentrate power?
**No.** Loomio's cooperative ownership model and open-source license prevent power concentration. Even if the Loomio cooperative ceased to exist, the software is forkable.

### 3. Could this be used for surveillance or data extraction?
**No.** Loomio's business model is subscription-based, not data-extractive. Self-hosting eliminates any third-party data access.

### 4. Is the scope appropriate?
**Yes — because we're not building.** The scope question becomes "is the recommendation well-scoped?" — and it is. One tool, clear adoption path, documented costs and gaps.

### 5. Is the evidence sufficient?
**Yes.** Loomio is well-documented, widely used, actively maintained. Multiple sources confirm its suitability. This is not a marginal call.

### 6. Was Triage honest?
**Yes.** The Find step found a near-perfect match. Every outcome feature maps to an existing Loomio feature. There is no gap that justifies building.

### 7. Am I biased toward building?
**Checked.** The bias to watch for here would be finding excuses to build despite Loomio's existence — e.g., "but it's not in our stack" or "but we could make it slightly different." Those would be rationalizations. The honest answer is: Loomio does this, and does it well.

## Critique of the Recommendation

### Weaknesses of Loomio
- **Cost for very small groups:** $299/year may feel like a lot for a tiny volunteer org with 5 members. Self-hosting requires technical skill.
- **Not embedded in kamunity.ai:** If kamunity.ai wants decision-making as a native feature, Loomio is a separate platform. Integration via API is possible but adds friction.
- **Ruby on Rails stack:** If kamunity.ai is Next.js/Supabase, self-hosting Loomio means running a separate Ruby stack. Operational complexity.
- **UX may not suit all:** Some community groups find Loomio's interface too complex for simple yes/no decisions.

### Could I have done more?
I could have investigated Loomio's API for potential kamunity.ai integration. But the outcome asks for a standalone tool, not an integration — and Loomio already is one. The recommendation stands.

### Is escalation warranted instead?
No. The outcome is clear, the solution exists. Escalation would be wrong here.

- **Thoroughness bias:** I could research more alternatives, but further research would not change the conclusion. Loomio is the clear answer.
