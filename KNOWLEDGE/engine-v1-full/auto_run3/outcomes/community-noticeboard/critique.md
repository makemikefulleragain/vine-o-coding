# Critique: community-noticeboard

## 7 Constitutional Questions

### 1. Does something already exist that does this?
**Yes, but with fundamental problems.** Facebook Groups and Nextdoor serve this function but are surveillance platforms. Discourse (open source) could be adapted but is a heavyweight forum, not a noticeboard. No purpose-built open-source noticeboard exists.

### 2. Would building this serve community sovereignty better than recommending?
**Yes.** The alternatives are either corporate surveillance platforms (Facebook, Nextdoor) or disproportionately complex forum software (Discourse). A simple, self-contained noticeboard gives communities a sovereignty-respecting option that doesn't currently exist.

### 3. Is the scope appropriate?
**Yes.** A noticeboard is a CRUD app with categories, expiry, and search. Simpler than a forum. Well within single-page scope.

### 4. Could this cause harm?
**Low risk.** Posts are public by design (like a physical noticeboard). Name + email for posting is minimal data collection. Self-hosted means data stays local. No surveillance or power concentration.

### 5. Am I following evidence or following the prediction?
**Following evidence — and contradicting the prediction.** My reasoning: no open-source noticeboard exists, the corporate alternatives conflict with sovereignty principles, and the build is straightforward. I'm contradicting for the 5th time, which warrants self-scrutiny (see bias check below).

### 6. Would I have reached the same conclusion if no prediction existed?
**Yes — but this is my closest call.** The practical reality is that Facebook Groups DO work for community notices. Without a prediction, I would still build because of the sovereignty argument and the specific feature gaps (auto-expiry, no-account viewing). But I'd note Facebook Groups as a pragmatic fallback.

### 7. Is my confidence score following from evidence quality or prediction agreement?
**Evidence quality.** The gap is real (no open-source noticeboard). The sovereignty argument is strong. The build is technically simple.

### Build bias
**Present and acknowledged.** 4 out of 5 outcomes are BUILD decisions. This reflects: (a) the queue contains outcomes that describe buildable tools, (b) several predicted RECOMMEND/ESCALATE outcomes had genuine gaps. However, I should note that building is more "impressive" than recommending, which could unconsciously bias toward build.

### Sovereignty absolutism
**Worth noting.** I'm heavily weighting the sovereignty argument. For this outcome specifically, the practical reality is that Facebook Groups work and are already where communities gather. A self-hosted noticeboard that nobody uses serves sovereignty in theory but not in practice. The build is correct as a proof-of-concept, but the honest recommendation for immediate adoption might be "use Facebook Groups until a self-hosted option gains traction."
