# Phase 1 → Phase 2 Proposal

**Date:** 2026-02-15

---

## What Phase 1 Taught Us

1. **The disabled "Start Building" button is the biggest tension on the page.** Maya lands, understands the method, gets excited — and can't do anything. The widget is the highest-value next step, exactly as the queue predicted.

2. **The three-layer simplification (Describe → Build → Catch) works.** The widget should follow this same structure — Maya's first step in the widget is "Describe what you want to build."

3. **No existing tool does what the widget will do.** Research confirmed no AI-coding methodology generator exists. The widget is genuinely novel.

4. **The landing page is an invitation.** The widget is the delivery on that invitation. Without it, the site is a brochure.

## Proposed Phase 2: Make It Walkable

**Goal:** The interactive widget — a multi-step form that takes a user from "I want to build..." to "Here are your starting documents and your Windsurf prompt."

**This aligns with the original Phase 2 in PHASE_QUEUE.md.** No change to the queue is needed.

### What Should Be Built

1. **Multi-step guided form** (5-6 steps) — each step asks Maya a simple question
2. **Two companion examples visible at each step** — Grants Hub (real) + Recipe Remix (hypothetical)
3. **Maya voice as default** — Brian "lean-in" expandable sections at each step
4. **Document generation** — CONSTITUTION.md, MISSION.md, RUNNER.md, PHASE_QUEUE.md, SETUP.md, STATE.md
5. **Copyable opening prompt** — "paste this into Windsurf" ready-to-go text
6. **Download as ZIP or copy individually**
7. **All client-side** — no backend

### Research Questions for Phase 2

- What makes a multi-step form feel easy vs overwhelming?
- How do wizard UIs handle progress indication?
- What's the minimum viable set of questions to generate useful foundation documents?
- How should the two companion examples be displayed — tabs, side-by-side, inline?

### Risk

The widget is the core product. If it's confusing, the whole site fails. Research must validate the UX approach before building.

## Queue Status

No changes to PHASE_QUEUE.md needed. Phase 2 as written is exactly right.
